    How the numbers are made

    Everything on this page is an analytical model. Nothing here was measured on a cluster, and no benchmark result is claimed. The model uses published datasheet bandwidth and FLOPS, published model configs, and a few labelled assumptions.

    Memory

    KV bytes per token = 2 x L x n_kv x d_head x bytes
per GPU = 2 x ceil(L / PP) x ceil(n_kv / TP) x d_head x bytes
weights = non-embedding params x bytes + embeddings x 2
budget = HBM x gpu-memory-utilization
KV pool = budget - weights/(TP x PP) - activations - runtime
sequences = floor(pool blocks / blocks per sequence)

    Embeddings and the output head stay at 16 bit when the rest is quantized. Blocks are 16 tokens, as in vLLM. Parameter counts are derived from layers, hidden size, heads and FFN width, then checked against the published totals in the test suite.

    Latency

    decode  = max(bytes / (BW x eff), FLOPs / (peak x eff))
          + 2 x L x all-reduce + launch overhead
prefill = max(weight reads + KV writes, 2 x params x tokens
          + 2 x L x n_q x d_head x prompt^2) + the same overheads
all-reduce = latency + 2 (TP - 1) / TP x bytes / link

    Decode reads every weight once per step, so it is bandwidth bound until the batch is large. Prefill is compute bound. L40S has no NVLink, so tensor parallel pays PCIe all-reduce costs. A100 has no FP8 Tensor Cores, so FP8 only saves memory there.

    GPU specifications

    Throughput is dense Tensor Core throughput. The H100 and H200 pages print only the figures with structured sparsity (1,979 TFLOPS FP16 and 3,958 TFLOPS FP8), so the engine uses half of those. Sources are the NVIDIA datacenter pages for H100, H200, L40S and A100.

    Model architectures

    Shapes come from each model's config.json on Hugging Face (ungated mirrors where the original is gated) and, for Nemotron-4-340B, Table 1 of the technical report.

    What it does not model

    • Mixture of experts routing, speculative decoding, prefix caching and disaggregated prefill.
    • Gemma-2 sliding window layers, which would reduce KV below what is shown.
    • Allocator fragmentation, CUDA graph capture sizes beyond a flat estimate, and NCCL topology effects beyond a single latency and bandwidth per link.
    • Queueing in the workbench. The router adds a simple per replica prefill queue and a batch snapshot at admission.
    • Task quality. The router capability score is a size proxy (log of parameter count, 400B equals 1.0). Replace it with your own eval results.
